# Independent audit of the Linux ransomware detector

## Audit brief

The reviewer received the project objective, implementation details, frozen benchmark metrics and exact artifact paths in a fresh context without conversation history. It was asked to challenge the evidence for early Linux detection and file preservation, independently reproduce the metrics, audit the collection and scoring paths, and distinguish the Docker demo, comparative benchmark and production claims. The assigned skills were scientific-critical-thinking and verification-before-completion. The audit read source, inert archives, frozen model bundles and benign fixtures.

## Reproduced results

The reviewer independently rescored all 314 GRU model–case combinations on CPU. Bundle hashes, per-case peaks, alert positions, confusion matrices, ROC-AUC and average precision matched the published report exactly. Both scorers reproduced 1 of 44 calibration alarms at the respective frozen cutoffs in batch and streaming mode. The bounded model and GRU refit had tensor-identical base weights.

| Test and frozen model | TN | FP | FN | TP | ROC-AUC | Average precision |
|---|---:|---:|---:|---:|---:|---:|
| Separate captures, either GRU | 98 | 2 | 0 | 5 | 1.000 | 1.000 |
| Same-stream GRU refit | 35 | 12 | 4 | 1 | 0.494 | 0.183 |
| Same-stream bounded context | 34 | 13 | 4 | 1 | 0.506 | 0.185 |
| Same-stream event count | 44 | 3 | 4 | 1 | 0.830 | 0.309 |
| Same-stream CNN | 47 | 0 | 5 | 0 | 0.604 | 0.154 |

The count and CNN rows are new audit diagnostics on exactly the same mixed cases. The count model's sole alert arrived after 421 retained ransomware operations. Both GRUs alerted on one case by 120 retained ransomware operations, and each had nine false alarms in 47 mixed controls at a fixed early comparison cutoff of 367 total operations. At that cutoff, the refit and context ROC-AUCs were 0.632 and 0.636. Peak AUC over the entire horizon and accuracy at an early operating point measure different behavior. ## Findings

1. **Critical for generalization. Positive evaluation was exposed to model selection.** The bounded-model selection receipt evaluates 72 configurations against the same five positives used for the reported recall. DarkSide's three operation prefixes are identical through event 32, and Erebus's two are identical through event 120. At the reported alert positions, the five successful decisions span two distinct token prefixes. The five cases remain useful for regression. A credible recall estimate requires held-out source captures or families that are locked before model and threshold selection. [Selection receipt](../../runs/linux-gru-context-bounded/selection.json) · [Selection code](../../scripts/benchmark_linux_context.py)
2. **High. The live collector and offline evaluator can disagree on event order.** Offline orders by the computed completion timestamp. Live emits tracer line order while clamping elapsed time. An inert unfinished/resumed syscall fixture produced `close, write` live and `write, close` offline. This can change the state and score on the same observed calls. The observer stops scoring at 2,048 retained operations. Specify a shared ordering rule and continuous scoring behavior, and test overlapping calls, ties, and boundary behavior. [Offline collector](../../scripts/capture_linux_benign.py#L129) · [Live collector](../../scripts/capture_linux_benign.py#L332) · [Frozen horizon](../../src/raneval/observe_linux.py#L14)
3. **High. Source instrumentation is associated with class.** File and directory identity appeared on 91.04% of benign test events and 65.07% of positive events. All five positives reached the 2,048-event cap, while 37 benign captures were shorter. Differences in metadata coverage and observation length can contribute to separation. Measure equal-length, same-collector samples on unseen hosts and report a source-only diagnostic. [Context construction](../../src/raneval/context.py) · [Mixed evaluator](../../scripts/evaluate_linux_mixed.py)
4. **High. The write gate demonstrates a response on generated fixtures.** The ONNX replay verifies that a score crossing prevents later dummy marker appends. Each retained observation receives its own marker target, regardless of the observed operation, and the alerting event's marker has already been appended. The protected file count represents those dummy appends, and the replay CNN differs from the GRUs under study. An outcome benchmark needs timestamped attempted and completed file effects tied to the proposed intervention. [Replay scorer](../../demo/linux_dashboard/server.py#L113) · [Marker gate](../../demo/runner.py#L52)
5. **High. The same-stream test exposes failure under one schedule and leaves attribution open.** The positive case score uses every retained operation, including benign warmup or background. In the only detected positive, refit first crossed on a benign operation and context first crossed on an injected operation. Its background trace alone was exactly one ULP below both cutoffs. The run had no positive-stream alarms before onset, yet it lacks a matched benign-injection counterfactual using the same background. Vary mixing ratio, start offset, reset phase and benign workload using paired controls. Report both first alarm and onset-qualified detection. [Mixing and score definitions](../../scripts/evaluate_linux_mixed.py#L50)
6. **Medium. Context does not measure stable file identity or damage.** In the parser fixture, a successful rename used the source pathname as identity and a later open of the destination acquired a different identity. A successful write to a pipe was retained with a positive byte return and null file and directory IDs. A syscall return size measures bytes reported by the operation. Validate what counts as a file target and test rename, descriptor reuse and non-file I/O against the claimed features. [Context projection](../../scripts/capture_linux_benign.py#L76) · [Context features](../../src/raneval/context.py)
7. **Medium. The cutoff has a thin numeric boundary.** The cutoff is one representable float above the calibration boundary. Batch and streaming scores differed by about 10⁻⁷, while this audit found zero decision flips on the 44 calibration captures. Calibrate using the intended runtime score path and add threshold-boundary tests. [Threshold implementation](../../src/raneval/core.py#L160)
8. **Medium. The dashboard omits the most recent mixed-stream result.** The Docker comparison serves the bounded-v4 result and its 44 benign captures. An audience that only opens that tab will miss the larger v5 test and the deterioration under interleaving. Show the latest mixed result with cohort, model, operating-point and source labels. [Staged comparison](../../runs/linux-dashboard-inputs/benchmark.json) · [Mixed results](linux-gru-mixed-test.md)

## Additional challenge tests

- **Background sensitivity.** Crossing the same five positive recordings with all five original background captures produced 7/25 detected combinations for refit and 9/25 for bounded context. Refit caught 1/15 DarkSide and 6/10 Erebus combinations. Context caught 1/15 DarkSide and 8/10 Erebus combinations. All detections were by ransomware event 120. These repeated combinations share inputs and show how strongly pairing affects results.
- **Counterfactual check of the sole initial detected stream.** With the same SQLite background and the 95 remaining benign captures substituted for the injected recording, zero controls had alerted by the original positions of events 221–222. By the full horizon 42/95 refit and 46/95 context streams had alerted. The original early crossing therefore has some specificity to that pairing, while general false alarms remain high under this schedule.
- **Provenance and isolation.** Rebuilt all five positive rows exactly from two hash-verified CRIBA archives. Verified 110 distinct v5 capture sequences, including the ten unused reserve runs, with zero exact overlap with prior exclusions. Benign capture workspaces are deleted after projection, so the audit could verify the prepared benign traces and receipts. Ran 10 project and four demo unit tests successfully. The reviewed tests leave overlapping-call ordering, interleaving, and live calibration transfer untested.
- **Live Docker replay.** The localhost API independently returned a first alert at event 26 and blocked 358 subsequent marker writes. Every one of the 358 corresponding protected files retained its starting hash. The benign replay raised no alert. The running image was about 110 MB, with a nonroot UID, read-only root, one CPU, and a 384 MiB memory limit. The detector artifact identified itself as the earlier CNN.

## Verdict and release gates

| Claim | Audit verdict |
|---|---|
| A lightweight Docker replay can score a recorded trace and gate later dummy writes | Verified |
| The GRUs classify these five known recordings when each run has its own state | Reproduced on 100 fresh benign captures with two rotation alarms |
| File and process context improves early discrimination | The isolated results tie and both models fail on most shared-stream positives. The reused pairing grid is exploratory |
| The current model provides reliable host-wide detection or real damage prevention | Production evidence insufficient |

1. **Align collection and inference.** Specify one event order, identify which successful operations concern regular files, and use stable task and file identities where available. Require live and offline projected events and alert decisions to match on the same fixtures. Include overlapping syscalls, timestamp ties, PID reuse, rename, descriptor reuse, and recurrence reset.
2. **Test state scoped by task or workload against the pooled model.** Keep count, CNN and GRU baselines. Freeze all thresholds against the same intervention-level alert budget, including alarm aggregation across tasks. Use matched benign controls, several background workloads and schedule offsets, and the identical scoring horizon across models. Report alarm timing relative to onset, runtime resource usage, and both full-horizon and early performance.
3. **Lock an external evaluation.** Use genuine pre-recorded, family- and host-disjoint cases with comparable collectors. Predefine the 5% alarm target and minimum early recall. Reserve enough clean sessions and independent positives to produce decision-relevant intervals, then report the measured alarm rate and family-level results with uncertainty. Freeze model and thresholds before the holdout is scored.
4. **Keep dashboard evidence current.** Show the v5 interleaving failure next to the successful CNN fixture, identify the active model on each view, and use marker-write labels for the demo. Evaluate changes prevented only on separately recorded file outcomes with a paired response comparison.
