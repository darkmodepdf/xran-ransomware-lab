# Retrieved evidence, 2026-11-17

- CRIBA publisher repository: https://github.com/dsrhaslab/criba . Framework and released Linux traces; source revision can be pinned. Original paper https://jtpaulo.github.io/assets/files/2023/criba-srds23-taniaesteves.pdf describes syscall arguments, process/thread context and file correlations. These sources have a common publisher; they are not independent validation of detector quality.
- DIO parser https://raw.githubusercontent.com/dsrhaslab/dio/v1.1.0/dio-tracer/pkg/tracer/parser.go establishes file tags from device/inode/incarnation information, success-conditioned descriptor/file-tag recording. Local sample inspection: 386 lines of an existing DarkSide JSON member expose pid, tid, ppid, call_timestamp, return_timestamp, return_value, args, file_tag and rename fdata. Some calls lack inline paths. This is a schema spot-check, not an archive-wide audit. No member executed or extracted to the filesystem.
- EN2025 publisher https://zenodo.org/records/18218588 states 919 benign, 733 ransomware, 816 RAT, 792 spyware samples; operation logs without executable binaries; 77.9 GB decompressed total. Local 127,121-byte CAPE report spot-check exposes behavior.processes, process_id, parent_id, first_seen, call timestamps/thread_id/status/return/arguments and a NtQueryAttributesFile FileName argument. Exact file-handle lifecycle coverage and per-task/onset truth remain unverified. Existing preparation discards much of this context.
- Multi-Log https://www.multi-log.com/dataset/ advertises 60 ransomware and 55 benign disk applications with syscall/disk/network/performance traces. Google Drive link redirects to sign-in in the web tool. Contents, independent family coverage, executable-free packaging, and field compatibility unverified. License page https://www.multi-log.com/license/ displays MIT wording for software/documentation; dataset scope is not assumed from that alone.
- GuardFS original paper https://arxiv.org/html/2401.17917v1 explicitly extracts data before file access. Existing project schema audit records pid, entropy, op, ext, filename, timestamp, without completed-operation outcome. Suitable alternative for attempted-access semantics, not interchangeable with completed-operation CRIBA telemetry.
- Docker https://docs.docker.com/desktop/setup/install/windows-install/ distinguishes Linux and Windows container modes. Linux syscall execution does not reproduce Windows API execution. Docker runtime resource controls https://docs.docker.com/reference/cli/docker/container/run . Small image goals are proposed acceptance targets, not measured performance.
- ONNX quantization documentation https://onnxruntime.ai/docs/how-to/quantization.html . Do not assume export/quantization preserves threshold decisions; validate the actual backend and calibrate there.

Local implementation evidence, kept separate from external research: src/raneval/process_score.py supplies bounded per-actor histories; src/raneval/context.py supplies short causal context; scripts/prepare_context_criba.py currently defaults to a 2,048-event prefix and uses paths as normalized identities, so cannot be used unchanged for full file-lifecycle attribution. Existing research/linux-process-architecture.md documents substantial misses and reused positives. Historical weights are regression baselines, not evidence of a newly successful detector.
